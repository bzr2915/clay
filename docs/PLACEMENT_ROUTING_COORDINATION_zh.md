# 布局与布线的全局最优协调：问题陈述与现状

> 用途：与导师讨论、决定下一步架构。不是实现文档。
> 日期：2026-11-20。相关文件见 §7。
> 一句话：**布线已经能独立求到最优，也能吃程序生成的放置；但"布局最优"和"布线最优"拼起来不等于"全局最优"，而两者该按什么次序比较、要不要为此建下界，是需要先定的架构决策。**

## 1. 现在有什么

### 1.1 布线侧：已实现并验证

`clay/routing/` 下有 13 个原语，反相器剥线重布在两个工艺、四个样本、两种风格下全部通过：

| 样本 | 工艺 | 版本 | 状态 | 线长 | 通孔 | 核验 |
|---|---|---|---|---|---|---|
| GF180 9t `inv_1`（测试留出） | GF180 | learned / no_style | OPTIMAL | 8670 | 0 | 通过 |
| GF180 7t `inv_1` | GF180 | learned / no_style | OPTIMAL | 7630 | 0 | 通过 |
| GF180 9t `inv_2` | GF180 | learned / no_style | OPTIMAL | 15008 | 0 | 通过 |
| SKY130 `hd inv_1` | SKY130 | no_style / learned | OPTIMAL | 4540 / 4880 | 2 | 通过 |

证书性质：**在候选图上最优**（每网窗口内的层级 1 候选图）。不是连续空间最优，也不是官方 DRC 干净——本机无 Magic/netgen，核验只覆盖本地规则子集。

### 1.2 放置侧：已实现，独立运行

`clay/decision/core.py` 的 `coordinate()`：对放置候选做分支定界，目标面积，给出 `proven_optimal_in_scope`。它把候选逐个落盘（例如 `gf180_inv_1_v2/candidates/` 下 16 个 GDS）。

### 1.3 两侧的接口：刚打通

今天验证：布线器可以直接吃**程序生成的放置**，不再依赖答案版图。放置版图在标注层上写了网络标签，所以现有的 `reference_resolver` 原封不动可用，只需要把 `frame` 换成放置的 bbox。

## 2. 主问题：两个最优不能直接相加

### 2.1 问题的定义

设放置候选集 `P`，对每个 `p ∈ P` 有一个布线最优值 `R(p)`（给定 p，候选图上最小线长）。经典的联合问题是：

```
对加权：  min_{p ∈ P}  [ 面积(p) + λ·R(p) ]
对字典序：min_{p ∈ P}  ( 面积(p), R(p) )     先比面积，再比布线
```

现在的流程是"先选面积最优的 p，再对它求 R(p)"。**这不是上面任何一个问题。**

### 2.2 今天测到的反例（关键证据）

用 `gf180_inv_1_v2` 的 16 个放置候选，逐个布线并核验：

| 面积 | 候选数 | 其中可布通且核验干净 |
|---|---|---|
| 462 336（最小） | 4 | **2** |
| 487 104 | 4 | **0** |
| 491 232 | 8 | 3 |
| 合计 | 16 | **5** |

三个直接结论：

1. **只看面积会选到布不通的放置。** 最小面积那一档 4 个候选里 2 个布不通；487 104 那一档**一个都布不通**。
2. **面积相近的放置，布线质量差很多。** 可布通的 5 个里，面积跨度只有 6.3%（462 336–491 232），线长跨度 58%（9248–14 631）。
3. 所以"面积优先"这个次序本身可能就是把布线质量压掉了：一个面积大 6% 的放置可能线长好一半。

（这些数字来自 `gf180_inv_1_v2`，是训练样本的一版。用于说明现象，不作为泛化证据。）

### 2.3 为什么"拼起来"缺一块

要让联合搜索保持精确，需要"给定放置的布线下界" `L(p) ≤ R(p)`，且要便宜。有了它，执行核心可以：

```
若 面积(p) + λ·L(p)  已不优于当前最好完整解 → 剪掉，不必求解布线
```

现在没有 `L(p)`，所以只能对每个候选**完整求解一次布线**。16 个候选 × 约 3 s 还可以扛；候选上百就不可行。这是 `route_bound` 的作用。

## 3. 可以达到的四种"最优"，以及各自代价

| 级别 | 定义 | 证书能写什么 | 现在可做吗 | 代价 |
|---|---|---|---|---|
| **L0** | 面积最优放置，对该放置布线最优 | 两条独立结论，**互不保证** | 可以 | 已基本完成 |
| **L1** | 在已枚举候选中，取"可布通者中面积最小" | 范围限定在**已枚举的 N 个候选** | **可以，今天已验证** | 2 分钟 |
| **L2** | 在已枚举候选中按字典序 `(面积, 线长)` 最优 | 同上 | **可以，今天已验证**（16 个全解） | 2 分钟 |
| **L3** | 在放置候选集 × 布线候选图上联合最优 | 联合证书 | 需要 `route_bound` | 3–5 天 |
| **L4** | 连续空间最优 | — | **不能**（八方向多网无完备性定理） | 不建议追 |

**当前处在 L0 和 L1 之间**：接口通了，但还没固化成流程。

## 4. 需要决策的三件事

### 4.1 目标次序：面积优先，还是允许面积换布线质量

| 选项 | 含义 | 后果 |
|---|---|---|
| **字典序**：面积 → 线长 | 先面积最小，再在其中选线长最短 | 范围小、可穷举、可证明；但可能为了几 % 的面积放弃大量布线质量 |
| **加权**：面积 + λ·线长 | 允许用面积换布线 | 更接近真实设计指标；但 λ 是人为的，且候选空间大得多 |
| **面积优先 + 布线只作可行性门槛** | 布不通的排除，其余按面积 | 最省事；但完全不比较布线质量 |

今天的数字说明这不是纯理论问题：面积 487 104 那一档全布不通，而 491 232 有三个可布通。如果目标是"面积优先"，那 491 232 的解永远不会被选，即使它可能是唯一可行的。

### 4.2 声称的"最优"范围

三个层次的诚实程度不同，需要选一个写进证书：

- "放置面积最优；布线对该放置最优"（L0，两条独立结论）
- "在已枚举的 N 个放置候选中，所选者最小面积且可布通"（L1）
- "在放置候选集 × 布线候选图上联合最优"（L3）

**注意**：即使 L3，那个"候选集"也是协调核心搜索出来的有限集合，不是放置空间的完备枚举。这一点必须写清。

### 4.3 要不要现在建 `route_bound`

| 现在建 | 现在不建 |
|---|---|
| 3–5 天 | 0 |
| 候选数上百或上千时才能受益 | 16–50 个候选直接穷举即可 |
| 需要一个可证的下界构造（无障碍最小 Steiner 等） | 换成比较器/OTA 时可能不得不建 |

## 5. 过程中遇到的具体问题（供参考）

这些不是协调问题本身，但会影响"能不能信任结论"。

### 5.1 已修：三个静默正确性 bug

都出现在**契约测试全绿**的情况下：

| bug | 表现 | 根因 |
|---|---|---|
| 同网判据用成对互斥 | 458 个"冲突"里 0 个是真的 | 同网合法性是**合并几何**的性质，不是候选对的 |
| 构造证明用了不可行的解 | SKY130 直接 INFEASIBLE | 构造解只查了跨网，没查同网凹口，却被当成"第 1 层最优=0"的证据 |
| 凹口归因缺口 | 同一个凹口每轮复现，永不收敛 | 凹口一侧是本网输入金属时找不到"候选所有者"，整条违规被跳过 |

**教训**：契约测试（P1–P7）保证的是"不写死 PDK/电路/网络名"，它管不到"求出的解是否合法"。需要补一类"模型自洽"测试。

### 5.2 今天修：`bbox()` 解包错误

`_Conflicts.bbox()` 仍按旧的 3 元组解包，而 `items()` 已改成 2 元组。之前没暴露，是因为反相器旧样本跨网冲突在 lazy 第 1 轮后为 0，该路径几乎不被调用；换成生成的放置后跨网冲突真的出现，才触发。**这会影响所有多网场景，包括比较器。**

### 5.3 未解决：验收缺口

- **官方 DRC/LVS 未运行**（本机无 Magic/netgen）。所有"核验通过"只覆盖 Pack 的本地规则子集。
- 斜向金属的专属规则（斜线最小宽度、锐角、斜线间距）因此**完全未验证**。

## 6. 建议的决策顺序

如果按"先能交付、再求严谨"：

1. **定目标次序**（4.1）——不定这个，后面全是空转
2. **定声明范围**（4.2）——写进证书
3. **固化 L1/L2 流程**（约 1 小时）——现在还是 `work/` 下的一次性脚本
4. **换留出样本验证**（约 10 分钟）——现在的 16 个候选属于训练样本
5. **之后再决定要不要建 `route_bound`**（4.3）

如果按"先求严谨"：先做第 5 项的 `route_bound`，但那样在 16 个候选的规模上收益为零。

## 8. 讨论时值得问的几个问题

1. 面积优先是否合理？标准单元的高度/宽度约束下，"面积"还有多少可压缩空间，值得为它牺牲布线质量吗？
2. 如果采用加权，λ 怎么定？按线长的等效电容？还是按后端时序的灵敏度？
3. "在已枚举的候选里最优"这个声明，对论文/验收来说够不够？
4. 官方 DRC 能不能装起来？不能的话，所有"干净"的结论要打多大折扣？
5. 比较器阶段网数翻倍，模型规模会不会需要先做分解，而不是先做 `route_bound`？
